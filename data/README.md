## 三、数据清洗与预处理记录（附件5 第三章明确要求）

### 3.1 结构连接方式校验（四源交叉）

对 110 条 SMILES 做了四道独立校验：RDKit 离线自洽性、**PubChem PUG-REST 双向比对**
（名称→结构、结构→同义词表）、ChEMBL、NCI CACTUS。

| 结论 | 结果 |
| --- | --- |
| SMILES 可解析性 | **110 / 110 通过** |
| 分子式与分子量自洽 | **110 / 110 通过** |
| 与权威库 InChIKey 级一致 | **109 / 110** 精确一致 |
| 重复 / 错位结构 | **0 处** |

→ 110 条 SMILES 的连接方式与权威记录一致，未发现结构错配。

### 3.2 发现并修复的问题：立体化学缺失（导致结果不可复现）

| 问题 | 说明 |
| --- | --- |
| 现象 | 9 个分子的手性构型在 PubChem 源记录里**完全未定义** |
| 根因 | 取数时按**英文名**检索，命中了 PubChem 不带立体描述符的"**父记录**"<br>（例：`Camphor` → DL-樟脑 CID 2537，而非 (1R,4R)-(+)-樟脑） |
| 后果 | RDKit 3D 嵌入对未指定手性中心会**任选一个构型并静默固化**——换随机种子即改变，<br>而回读后的 SDF 中"未定义手性中心数"= 0，**看起来与确定构型的分子毫无区别** |
| 处置 | ① 依据 PubChem / ChEMBL 权威记录补齐构型；② **11 个分子用修正版 SMILES 重跑对接**；<br>③ **剔除 1 个**（#89 桔梗皂苷 D3，36 个手性中心全部未定义且公开库无解） |
| 结果 | 库由 110 → **109 个**；重跑后 5 个分子的通过/未通过归属发生变化，证实原归属是构型假象 |

**防护措施**：本项目在管线内置 **立体化学闸门**（`src/stereo_gate.py`），
六种策略 `auto|fix|enumerate|fail|warn|asis`；默认为 `auto`：
先用文件元数据修复 → 失败则枚举全部立体异构体（上限可配）→ 超限则**拦截并报告**，
不再允许静默任选。另提供只读体检工具 `src/stereo_audit.py`。

**闸门策略与判定码**（实现见 `src/stereo_gate.py` / `src/stereo_audit.py`）：

| 策略 | 行为 |
| --- | --- |
| `auto`（默认） | 先用文件元数据修复 → 失败则枚举全部立体异构体（上限可配）→ 超限则拦截并报告 |
| `fix` | 只用元数据修复；修不好即拦截 |
| `enumerate` | 强制枚举异构体 |
| `fail` | 检出即整批失败退出（非零退出码） |
| `warn` | 只警告，仍按原行为继续 |
| `asis` | 完全保持旧行为（用于复现历史结果） |

只读体检工具 `src/stereo_audit.py` 可对任意 SDF 目录输出逐分子的手性中心与异构体数，
退出码 0/1 可作流水线门禁。


### 3.3 去重与数据泄漏防控

- **去重**：全库按 InChIKey 精确匹配去重，**0 处重复**；
  唯一"骨架相同"的一对是 #47 儿茶素 / #48 表儿茶素，二者为 C2/C3 差向异构体，**属正确结果**。
- **数据泄漏防控**：本项目**不做训练**，因此不存在训练/测试集划分问题。
  受体结构（4KNG）与配体库（PubChem）来源相互独立，**无重叠**。
  对接所用的**位点**由本项目自己的盲对接独立确定（未参考任何外部已知配体位置——
  本靶点也不存在已知小分子配体）。
