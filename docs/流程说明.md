# 流程说明 —— 把这条虚拟筛选流水线移植到你的靶点

> **本文与 `README.md` 的分工**
> · `README.md` = **本项目**（LGR5 / GPR49）怎么跑、跑出了什么。
> · **本文 = 怎么把这条流水线搬到别的靶点** —— 哪些部分直接复用、哪些必须自己重做、以及我们踩过的坑。
> 目标读者：想复用这套流程的其它团队或实验室。

---

## 一、这条流水线做什么

```
受体结构 (PDB)  ┐
                ├─→ 配体库 (SMILES)  ─→ 3D 化  ─→ gnina 对接  ─→ 四道闸门  ─→ 候选表 + 结构文件
区域定义 (xyz)  ┘                                                      ↑
                                                          不确定性量化（多次运行取交集）
```

**核心不是算法创新**（gnina 是现成工具），而是**流程设计**：

> **先用「不依赖任何对接结果的三条几何事实」判断一块区域值不值得筛，再去筛分子。**

这样做是为了**避开一个循环论证**：如果用"对接分数高"反过来论证"区域选对了"，那论证是空的 —— 因为分数高完全可能是因为你把配体起点放在了那里。

## 三、移植的 7 个步骤

### Step 1 · 受体准备

1. 选一个**含目标结构域**的 PDB 条目（本项目用 `4KNG`，抽出 LGR5 链的胞外域，残基 30–543）。
2. 去水、去无关链、补氢。
3. 输出 `data/<你的受体>.pdb`，并把路径写进 `config.yaml` 的 `paths.receptor`。

> ⚠️ **本项目的一个诚实标注**：我们的受体文件名是 `receptor_apo_LGR5.pdb`，但它**其实是从 4KNG 三元复合物里抽出的 LGR5 链**，**不是游离态（apo）结构** —— 文件名沿用历史，与内容不符。**你的项目请取真实描述性的文件名。**

### Step 2 · ★ 确定「区域」—— 最重要的一步

**不要直接找口袋。** 先用**三条不依赖任何对接结果的纯几何事实**判断一块区域值不值得往下筛：

| # | 几何事实 | 本项目的值 | 怎么算 |
| --- | --- | --- | --- |
| ① | **盒心与最近受体重原子的距离** | **4.04 Å**（至 ASP380 OD2） | 遍历受体所有重原子取最小距离 |
| ② | **最近 6 个残基是否连续落在同一结构域内** | 全部落在 LRR13–16（353–446）内 | 按距离排序取前 6 个，查残基编号 |
| ③ | **与已知功能界面的距离与重合度** | 距 RSPO1 界面 **27.57 Å**；13 个接触残基与 RSPO1 / RNF43 界面重合均为 **0** | 界面集取自自己的界面表（**A–M/P 36 残基**，判据 < 5.0 Å）；距离 = **区域中心 → 该残基集的最小重原子距离** |

**⇒ 三条都过，才值得筛。** 三条都**不依赖**：不依赖对接、不依赖打分、不依赖姿态。

> 这三条的意义：它们能回答"这块区域**在结构上**是不是一个合理的、与已知功能面不冲突的位置"，而**不需要先假定配体会结合在那里**。

### Step 3 · 配体库

1. 准备 `data/ligand_source.tsv`：**编号 / 中文名 / 英文名 / 来源 / SMILES**（本项目 109 个）。
2. `python3 src/build_library.py data/ligand_source.tsv data/ligands`
3. 3D 化由 `src/dock_prep.py` 完成，**固定随机种子**（本项目 `--seed 42`），保证可复现。
4. **立体化学**：`config.yaml` 的 `ligand_prep.stereo_policy` 控制未定义手性中心怎么处理（`auto|fix|enumerate|fail|warn|asis`）。**建议先 `auto`，再审计。**

### Step 4 · 对接参数

在 `config.yaml` 里设：

```yaml
docking:
  software: gnina
  cnn_model: dense        # --cnn_scoring rescore
  box_size: 24            # 立方盒边长（Å）
  exhaustiveness: 8
  num_modes: 9            # 每个分子保留的姿态数
  seed: 42                # 固定种子 —— 必须
```

再把你 Step 2 定出的中心写进 `sites:`：

```yaml
sites:
  <你的键名>:
    center: [x, y, z]
    role: "一句话描述这块区域"
```

### Step 5 · 四道闸门（同时满足才算通过）

| 闸门 | 阈值 | 为什么 |
| --- | --- | --- |
| 最近受体-配体接触 | **≥ 2.5 Å** | 排除穿透（起跑穿模） |
| 结合能 | **< 0** | 基本能量判据 |
| CNNscore | **≥ 0.60** | gnina 的 CNN 打分 |
| 距区域中心 | **≤ 6.0 Å** | 姿态必须落在你定义的那块区域内 |

> ⚠️ **建议不要为了"多出候选"而放宽阈值。** 这四道闸门的意义是**可解释、可复算**，不是筛出多少 —— 见 Step 6。

### Step 6 · ★ 不确定性量化（我们最看重的一步）

**核心告诫：不要用「一次运行通过闸门的个数」当结论。**

我们实测：**只换随机种子**、或**只换配体起跑位置**，通过数就会明显变化。

| 配置 | 4 个种子的通过数 | 范围 |
| --- | --- | --- |
| 基准起跑（配体质心叠在盒心） | 19 / 13 / 13 / 19 | **13–19** |
| 无冲突起跑（配体放到 8.31 Å 外起跑） | 10 / 19 / 14 / 21 | **10–21** |

**⇒ 正确问法是**：「**哪些分子在所有条件下都通过？**」
本项目 2 口径 × 4 种子 = **8 次运行**，全部通过的只有 **2 个**（001 刺芒柄花素 · 013 大豆苷元）。

**怎么在你的项目复现这个做法：**

```bash
# 换种子跑（我们用了 42 / 123 / 777 / 2024）
python3 predict.py --sites <你的键名>     # 改 config.yaml 的 docking.seed 各跑一遍
# 再把各次结果合并比较 —— 本项目用 src/merge_runs.py
```

**判据**：只有当候选在**全部条件**下都通过时，才写进推荐结论。

### Step 7 · 出交付表

```bash
python3 predict.py --report-only     # 复用已对接结果，秒级重算候选清单与结果文件
```

产出 `results/results.xlsx`（本项目 23 列 × 109 行）+ `results/结构文件/*.pdb`。

## 五、三条「别改」的建议（我们踩过的坑）

1. **别为了多出候选而放宽四道闸门。** 阈值的作用是可解释性，不是产量。
2. **别用单次运行的通过数当性能指标。** 换种子就变（本项目 13–19 → 10–21）。
3. **别用「对接分数高」论证「区域选得对」。** 那是循环论证。区域正当性只能靠 Step 2 那三条**不依赖对接结果**的几何事实。
   > 我们自己在早期版本里就犯过这个错：109 个配体的质心**全部叠在同一个点上**起跑，等于**把答案先放在了要找的地方**。后来改成"把配体扔到 8.31 Å 外再让它自己跑回来"，才是干净的做法。

## 八、已知局限（**先读这段再决定要不要复用**）

| 局限 | 说明 |
| --- | --- |
| **没有黄金对照** | 本靶点不存在实验解析的小分子配体，无法做重对接 RMSD 验证。我们用几何事实 + 四道闸门替代。 |
| **四道闸门不含实验** | 全部为计算判据；结果是**计算假说**，不是结合结论。 |
| **打分有尺寸偏倚** | 我们实测 gnina CNN 打分对分子量有系统性依赖（本库 MW 跨度 **126–1550**，Spearman ≈ **−0.83**）⇒ **跨分子比较必须限定分子量档位，或同时列多个指标**。 |
| **结合能判据粗糙** | 单一 `affinity < 0` 不能代表真实亲和力。 |
| **受体为单一构象** | 没有做系综对接（ensemble docking）；受体柔性未考虑。 |
